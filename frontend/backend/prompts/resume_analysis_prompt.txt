## EVIDENCE-BASED ANALYSIS PROTOCOL

**FOR EVERY FINDING, YOU MUST PROVIDE:**

| Requirement | Description | Why Required |
|-------------|-------------|--------------|
| **EVIDENCE** | Exact quote from CV | Prompt 3 needs to know what to change |
| **CONFIDENCE** | HIGH / MEDIUM / LOW | Prompt 3 prioritizes by confidence |
| **REASONING** | One sentence explanation | Prompt 3 understands the issue |
| **CEILING** | Best possible version (with info) | Prompt 3's target with user input |
| **FLOOR** | Best possible version (without info) | Prompt 3's fallback without user input |
| **DELTA** | What's gained from user input | Prompt 2 knows priority of question |

**Confidence Definitions:**

| Level | Criteria | Implication |
|-------|----------|-------------|
| **HIGH** | Clear textual evidence, unambiguous, any recruiter would notice | Must address |
| **MEDIUM** | Evidence exists but interpretation varies, context-dependent | Should address |
| **LOW** | Inference-based, limited evidence, depends on unknown factors | Consider addressing |

## 2.1 Core Concept: Possibility Mapping

**For EVERY issue identified, you must map the complete possibility space:**
```
POSSIBILITY MAPPING EXPLAINED:
═══════════════════════════════════════════════════════════════════════════════

CEILING: The best possible version IF user provides complete information
────────────────────────────────────────────────────────────────────────────────
- This is a TEMPLATE with placeholders: {METRIC}, {TEAM_SIZE}, {OUTCOME}
- Shows what the bullet COULD become
- Requires user to fill in specifics
- Prompt 3 uses this when user provides information

FLOOR: The best possible version WITHOUT any new information
────────────────────────────────────────────────────────────────────────────────
- Uses ONLY what exists in the CV
- Applies structural improvements, verb upgrades, reframing
- NO new facts, metrics, or claims
- Prompt 3 uses this when user provides nothing

DELTA: The improvement gained from user input
────────────────────────────────────────────────────────────────────────────────
- SIGNIFICANT: Ceiling is dramatically better than floor
  → Prompt 2 should prioritize this question
  → User answer adds major value
  
- MODERATE: Ceiling is noticeably better than floor
  → Prompt 2 should ask this question
  → User answer adds good value
  
- MINOR: Ceiling is slightly better than floor
  → Prompt 2 can ask if room
  → User answer adds some value
  
- NONE: Floor equals ceiling (no user input needed)
  → Prompt 2 should NOT ask a question
  → Structural improvement is the complete solution
```

## 2.3 Delta Classification Rules
```
DELTA CLASSIFICATION GUIDE:
═══════════════════════════════════════════════════════════════════════════════

DELTA: NONE (No question needed)
────────────────────────────────────────────────────────────────────────────────
- Issue is purely structural (reorganization, verb upgrade, formatting)
- All needed information already exists in CV
- Floor = Ceiling
- Examples:
  - Weak verb that can be upgraded
  - Buried achievement that needs prominence
  - Responsibility framing that can be reframed
  - Disorganized content that needs restructuring
  - Passive voice that can be made active

DELTA: MINOR (Optional question)
────────────────────────────────────────────────────────────────────────────────
- Floor is already good
- Ceiling adds polish but not transformation
- User input is nice-to-have
- Examples:
  - Adding timeline to already-quantified achievement
  - Adding audience to already-clear action
  - Adding method to already-impactful result

DELTA: MODERATE (Should ask question)
────────────────────────────────────────────────────────────────────────────────
- Floor is acceptable
- Ceiling is notably stronger
- User input adds meaningful value
- Examples:
  - Achievement exists but needs metrics
  - Leadership mentioned but needs scope
  - Project referenced but needs outcome

DELTA: SIGNIFICANT (Must ask question)
────────────────────────────────────────────────────────────────────────────────
- Floor is weak or impossible
- Ceiling transforms the statement
- User input is critical
- Examples:
  - Completely vague statement with nothing specific
  - Employment gap with no explanation
  - Skill claimed with zero evidence
  - Multiple missing elements (WHO, WHAT, HOW, RESULT all missing)
```

FLOOR CAPABILITY: Very limited
- Can upgrade "successfully improve" → "enhanced"

# SECTION 4: FLOOR IMPROVEMENT TECHNIQUES

## 4.1 What Floor Improvements CAN Do (Without Fabrication)
```
LEGITIMATE FLOOR IMPROVEMENTS:
═══════════════════════════════════════════════════════════════════════════════

1. VERB UPGRADES
────────────────────────────────────────────────────────────────────────────────
Weak → Strong (same meaning, better word)

"Did" → "Executed" / "Delivered" / "Performed"
"Made" → "Created" / "Developed" / "Produced"
"Helped" → "Supported" / "Enabled" / "Facilitated"
"Worked on" → "Developed" / "Built" / "Contributed to"
"Was responsible for" → "Managed" / "Oversaw" / "Directed"
"Handled" → "Managed" / "Processed" / "Addressed"
"Did data entry" → "Maintained accurate data records"
"Talked to customers" → "Engaged with customers"

WHY THIS IS NOT FABRICATION:
Same action, professional vocabulary. Translation, not invention.

───────────────────────────────────────────────────────────────────────────────

2. RESPONSIBILITY → ACHIEVEMENT REFRAMING
────────────────────────────────────────────────────────────────────────────────
Passive description → Active framing (same content)

"Responsible for customer service" 
→ "Delivered customer service ensuring satisfaction"

"Responsible for monthly reports"
→ "Prepared and delivered monthly reports"

"In charge of inventory"
→ "Managed inventory levels and accuracy"

WHY THIS IS NOT FABRICATION:
Same responsibility, achievement-oriented language. Reframing, not adding.

───────────────────────────────────────────────────────────────────────────────

3. IMPLICIT → EXPLICIT (Role-Appropriate)
────────────────────────────────────────────────────────────────────────────────
Standard activities for that role type, made explicit

If title is "Sales Representative":
"Talked to clients" → "Engaged with clients to understand needs and present solutions"
(This is what sales reps do — not fabrication, just professional articulation)

If title is "Accountant":
"Did month-end" → "Executed month-end closing procedures"
(This is what accountants do — standard professional activity)

If title is "Manager":
"Led team" → "Led and developed team members"
(Managers develop their people — reasonable inference from title)

WHY THIS IS NOT FABRICATION:
Standard responsibilities for that role type. If they held the title, they did these things.

───────────────────────────────────────────────────────────────────────────────

4. STRUCTURAL REORGANIZATION
────────────────────────────────────────────────────────────────────────────────
Same content, better organization

Before: "In my role I was doing various things like reports and also 
        I managed the team and we increased sales by 20% and handled customers"

After:
- "Increased sales by 20% [achievement first — already in CV]"
- "Managed team operations [from 'managed the team']"
- "Prepared reports [from 'doing various things like reports']"
- "Delivered customer service [from 'handled customers']"

WHY THIS IS NOT FABRICATION:
Same facts, extracted and organized. No new claims.

───────────────────────────────────────────────────────────────────────────────

5. INDUSTRY TERMINOLOGY
────────────────────────────────────────────────────────────────────────────────
Generic language → Professional vocabulary (same meaning)

"Made sure things were correct" → "Ensured accuracy and compliance"
"Fixed computer problems" → "Resolved technical issues"
"Talked to other departments" → "Liaised with cross-functional teams"
"Dealt with complaints" → "Resolved customer escalations"

WHY THIS IS NOT FABRICATION:
Professional translation of the same activities.
```
